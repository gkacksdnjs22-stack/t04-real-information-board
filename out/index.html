      실제 조회값을 ALEPH 과정 기록에 옮기기
      아래 항목은 저장된 실제 기록에서 가져옵니다. 날짜를 선택한 뒤 각 값을 복사해 ALEPH의 「선택 과정 기록 남기기 → 실제 공개 원천 기록」에 붙여 넣으세요.
      

      

      과정 기록은 제출·강사 승인·마스터 승인을 막는 조건이 아닙니다. 다만 정본의 실제 날짜·값 대조 평가에는 서로 다른 플랫폼 KST 날짜의 t04_day 영수증 2건이 사용됩니다. 앱 조회 뒤 같은 날에 기록을 남기고, 플랫폼의 작성 시각을 확인하세요. 이 앱은 영수증을 발급하지 않습니다.

      공개 심사 화면에 실제 기록 남기기
      일별 기록은 현재 브라우저에 저장됩니다. 다른 사람의 브라우저에는 자동으로 전달되지 않습니다. 실제 기록을 조회한 뒤 아래 버튼으로 보존본 HTML을 내려받아, 공개 결과물의 index.html로 배포하면 심사자가 같은 두 날짜의 기록을 볼 수 있습니다.
      공개 원천 데이터와 응답만 포함합니다. 합성 실험 상태와 개인 기록은 포함하지 않습니다. 별도 증거 ZIP이나 인증 파일을 제출할 필요는 없습니다.
      

      30초 확인 방법
      ① 어디에서: 「검사 화면」의 실패 실험.
      ② 무엇을 하면: 정상 기준 준비 → T04-TIMEOUT → 다시 시도 (3단계).
      ③ 통과 모습: 105 pt · stale/timeout · 1행에서 120 pt · fresh/none · 2행으로 복구, 변화 +15 pt. 같은 날짜의 record ID 유지.
      ④ 안 될 때: 오류별 설명·다음 행동과 오래된 마지막 정상값 표시. 실제 조회가 한 번도 없으면 값을 만들지 않고 오류 표시.
      

      제출 전에 확인할 것
      • 결과물 주소: 공개 HTTPS URL 한 개.
      • 소스 주소: 전체 40자리 또는 64자리 소문자 commit을 포함한 고정 HTTPS URL 한 개.
      • 두 주소가 새 시크릿 창에서 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 열리는지 확인.
      • 확인법 4줄과 AI·내 판단 3줄을 실제 작업에 맞게 작성. 각각 1,500자 이내.
      • AI에게 맡긴 일 / 직접 판단한 일 / AI 제안을 따르지 않은 일(없으면 이유)을 구분. 본인의 판단은 본인이 작성.
      제출 → 강사 승인 → 마스터 승인 → 이후 로컬 일괄 채점 순서입니다. 접수·승인과 조건 충족 평가는 분리됩니다. 기다린 시간은 과제의 6~7시간 작업시간에 포함하지 않습니다.
